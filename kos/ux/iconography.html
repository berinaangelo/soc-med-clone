Icon decision — Single Thread

Three ways to draw the mark

The palette settled on one hue tuned only by lightness and saturation. The type settled on one sans pairing, mono reserved for identity alone. Icons are the next surface asking the same question: what's the one thing that's allowed to change, and what does it mean when it does? Three recommendations below, each answering it differently — same eight glyphs, same nav bar, same follow button, only the rendering rule changes.

The fixture: eight functional icons the MVP actually needs — feed, directory, notifications, profile, compose, follow, edit, delete — drawn once as line geometry and reused via <use> in every candidate below, plus a nav bar, a directory row, and a post's edit/delete row so each rule shows up in real context, not just a swatch. Colors are the live Single Thread tokens, light or dark depending on how you're reading this.
315.4 — Plain Line

One weight, one fill state: none

The twist: color is the only lever, ever. Every icon is a thin, uniform line — 1.25px, never filled, never boxed — at rest or in any state. A current nav tab or a followed button doesn't get a badge or a background; it just shifts from muted to primary, the same way the palette itself carries meaning through lightness and saturation shifts on one hue rather than reaching for a new shape.

Stroke — 1.25px, constant everywhere Fill — never, in any state State signal — color shift only (muted → primary)

315.5 — Signal Weight

Line by default, fill only for meaning

The twist: a filled chip is reserved for state, never decoration. Every icon rests as a plain 1.75px line — a touch more confident than 315.4 — until something true has to be signaled: the tab you're on, the notification you haven't read, the person you already follow, the delete you're about to commit to. Only then does a solid chip appear. It's the same rule the palette already made: Success/Warning/Danger break the single hue only for status, never for brand. Here, fill breaks the outline only for state, never for brand.

Stroke — 1.75px at rest, outline only Fill — a solid chip, state-triggered only State signal — "Someone Noticed Me" gets a filled bell, not just a color

315.6 — Duotone Plum

Every icon rides a tinted chip, always

The twist: the palette's own hue becomes the icon's material, not just its accent. Every glyph — rest, active, unread, idle — sits on a soft plum tint with a solid stroke on top, all the time. It's the purest visual echo of "one hue carried by lightness and saturation," now applied to shape instead of just color. The boldest signature of the three, and the one with nothing held in reserve: if the chip is always there, it can't tell you when something changed.

Stroke — 1.5px, on a filled chip Fill — a plum tint, every icon, every state State signal — chip deepens to solid; nothing appears from nothing

Recommendation

Lean toward 315.5

Signal Weight

Every identity decision so far has landed on the same shape: one restrained default, broken only when it has to carry real meaning — never for decoration. The palette keeps Success/ Warning/Danger off-hue only for status. The type keeps mono off-sans only for identity. 315.5 is the icon language that keeps that promise: outline everywhere, and a fill only shows up where [[god-moments]] says something is actually happening — the bell fills the moment "Someone Noticed Me" is true, not before.

315.4 is the safer runner-up, and arguably the most literal read of "Single Thread" — if the palette itself never reaches for a new shape, an icon set that never fills either is defensible on principle. Worth keeping in the back pocket if 315.5's chip treatment feels heavier than the rest of the UI once it's built. 315.6 is the one worth a second look before ruling out — it's the most memorable at a glance, the kind of detail that makes screenshots recognizable — but a chip on every icon all the time has no reserve left to spend on the moment that actually matters, which is the opposite of what Success/Warning/Danger and mono-for-identity were both for.

Once one is picked, it gets written up the same way color and type were — decision, rationale, a role table — in kos/decisions/ux/iconography.md.
