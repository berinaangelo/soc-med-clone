Type decision — Single Thread

Three ways to set the type

Single Thread's palette made its case with one twist: a single hue, tuned only by lightness and saturation, because a text-first app shouldn't compete with its own words. These three recommendations each carry a typographic twist that plays the same game — not three unrelated font pairings, but three different answers to "what does restraint look like in type." Same brand colors, same mock post, only the type changes.

The fixture: every recommendation below sets the exact same content — a profile name, a bio line, a post, a follow notice, a button — so the type is the only variable. Colors are the live Single Thread tokens (#762D64 primary / #CA21A0 accent), light or dark depending on how you're reading this.
315.1 — Kept Voice

Fraunces + IBM Plex Sans + IBM Plex Mono

The twist: italic breaks rank for anything in the user's own voice. Names and posts stay in an upright serif/sans; the moment text is a bio or caption — someone describing themselves, not just posting — it drops into italic Fraunces, like a hand annotating the margin. Mirrors the palette's own exception: Success/Warning/ Danger break the single hue on purpose, because some things need to read differently.

315.2 — One Family

Newsreader, everywhere

The twist: one typeface for the entire product, the way one hue runs the entire palette. Newsreader is a variable serif with an optical-size axis — at display sizes it's a real headline face, at small sizes its letterforms simplify toward something closer to text type. Hierarchy comes only from size and weight, never a family switch. The most literal echo of "Single Thread," and the boldest bet here.

315.3 — Signed Sans

Sora + Inter + IBM Plex Mono

The twist: mono is reserved for identity, never for prose. Everything a person writes — posts, bios — sets in a calm humanist sans built for a fast scroll. The one place monospace appears is anything that names or timestamps a person: handles, "2m", follow notices. It functions like a signature, not a font choice — the same way the palette lets Success/Warning/Danger break the single hue only for status, never for brand.

Recommendation

Lean toward 315.3

Signed Sans

Single Thread's own god-moment list names "I Can't Stop Checking" — a feed people scroll fast, repeatedly. That favors a workhorse sans over a literary serif at UI sizes: Sora and Inter hold up in a dense, fast-scanning feed in a way a serif's finer detail doesn't at 14–15px. The mono-for-identity twist still gives the app a signature without asking every post to carry it.

315.1 is the safer runner-up — it already matches the voice of the palette specimen doc, so picking it costs nothing in consistency, and the italic-for-voice idea is worth keeping even if 315.3 wins on family. 315.2 is the one worth prototyping before ruling out: it's the purest expression of "Single Thread" as an idea, but a single serif family carrying buttons, badges, and timestamps is the riskiest bet on legibility at real UI sizes — worth testing on a real screen, not just this specimen, before deciding against it.

Once one is picked, it gets written up the same way the palette was — decision, rationale, and a token table — in kos/decisions/ux/typography.md.
